## ✅ 해결됨 (커밋 `126e3ec`, 2026-08-14 배포)

### 1. 정답이 5일 만에 재출현 — `workers/api/src/answer.ts`

날짜를 해시해 **매일 독립 추첨**하던 탓에 이미 나온 정답이 금방 다시 걸렸다.

| | 이전 | 이후 |
|---|---|---|
| 한 사이클(565일) 중복 | — | **0** |
| 1년간 서로 다른 정답 | 283개 | **365개 전부** |
| 최단 재출현 간격 | **5일** | **26일** |
| 요청당 비용 | ~0 | 4.9 µs |

사이클마다 풀 전체를 시드 셔플(mulberry32 + Fisher-Yates)하고 퍼즐 번호 순으로
소진한다. 서버 상태는 없다 — 날짜만 있으면 같은 답이 재현된다.

26일은 사이클 경계의 최악값(이전 사이클 끝 근처가 새 사이클 앞쪽에 배치될 때).
더 벌리려면 새 사이클 앞 구간이 직전 꼬리와 겹치지 않을 때까지 재셔플하면 된다.

### 2. 자동완성에서 구분 불가능한 동명 게임 — `apps/web/app/page.tsx`

한글명이 같은 그룹 218개 중 23개는 **영문명까지 같아** 화면상 완전히 똑같은 두 줄이
떴다. 어느 쪽을 골라도 절반은 엉뚱한 레코드라 이름을 정확히 알고도 추측 1회를 날렸다.

출시연도를 함께 표기해 해결. 구분 불가 그룹 **100 → 8**, 상위 1000위 포함분은
**21 → 1**.

> **병합은 오답이다.** 218개 중 98개는 한글명만 같을 뿐 실제로 다른 게임이다
> (루트 = Root/Loot, 마라케시 = Marrakesh/Marrakech, 갱스터 = The Gang/Gangster).
> 합치면 멀쩡한 게임이 추측 불가능해진다.

남은 8개는 원본의 완전 중복 레코드(이름·영문명·연도 전부 동일)이고 7개는 r1093
이하라 사실상 노출되지 않는다. 상위권은 뱀파이어 퀸(2016, r871/r1261) 하나뿐 —
UI가 아니라 데이터 정제 쪽 문제다.

### 3. 시리즈는 맞혔는데 편이 달라 정답이 아닌 경우

단독 플레이 가능한 형제가 여럿인 프랜차이즈가 많다(브라스: 버밍엄/랭커셔,
도미니언/장막뒤의 사람들). 시리즈를 정확히 떠올린 사람이 형제를 찍으면 점수·순위는
최상위인데 왜 정답이 아닌지 알 길이 없었다.

`/api/guess`가 `sameSeries: true`를 내려주고 추측 행에 파란 배지를 띄운다.
정답 후보 565개 중 **36%(203개)가 형제를 가진다**.

풀 묶음과 시리즈 판정이 어긋나면 "같은 시리즈"라고 알려준 게임이 풀에선 형제가 아닌
모순이 생기므로, `baseName`을 export해 **규칙을 한 곳으로 통일**했다.

## ⬜ 남은 작업

### A. 정답 풀을 bgg_id 기준으로 확장 (565 → 615) — 우선순위 높음

`baseName` 묶음이 **제목 앞부분만 같으면 다른 게임도 하나로 합쳐** 진 쪽을 정답 풀에서
영구 제외한다. 탈락 56개 중 **52개가 bgg_id가 다른 = BGG 기준 진짜 다른 게임**이고,
판/에디션 변형은 4개뿐이다.

영구 제외되고 있는 게임들:

```
브라스: 랭커셔 (r14)        팬데믹 레거시: 시즌 2 (r33)
도미니언 (r65)              그레이트 웨스턴 트레일: 뉴질랜드 (r66)
듄: 임페리움 (r68)          글룸헤이븐: 사자의 턱 (r78)
아컴 호러 (r332) + 3판 + 카드게임 개정판
스타워즈: X-윙 (r371)       테라포밍 마스: 아레스 익스페디션 (r787)
```

**자격 게임 621개 전부가 bgg_id를 갖고 있어** 신뢰할 수 있는 키다. `buildAnswerPool`의
묶음 키를 `baseName` → `bgg_id`로 바꾸면 위 게임들이 전부 살아난다.

위 3번(같은 시리즈 배지)이 **이 변경의 전제조건**이었다 — "브라스: 랭커셔"가 정답인 날
"브라스: 버밍엄"을 친 사람에게 시리즈가 맞다고 알려줘야 억울하지 않다. 이제 그게 있으니
안전하게 확장할 수 있다.

- [ ] `buildAnswerPool` 묶음 키를 bgg_id로 교체
- [ ] 풀 크기·프랜차이즈 편중 재확인(반지의 제왕 5편, 엑시트 3편 등이 동시에 후보가 됨)
- [ ] 배포 시 그날 정답 KV 고정 필요(풀이 바뀌면 순열도 바뀐다)

### B. `/api/stats` 60초 캐시가 제출 직후 갱신을 무력화 — 중간

## 운영 메모

### 정답을 바꾸는 배포는 KV 고정이 먼저다

정답 선택 로직이 바뀌는 배포는 **진행 중인 판을 깨뜨린다.** 순서:

1. 그날 정답을 KV에 고정 — `answer:YYYY-MM-DD` = 현재 라이브 값(id)
2. **5분 이상 대기** — `KV_CACHE_TTL`이 300초고 **미스(없음)도 캐시된다.**
   구 워커가 이미 그 키를 읽어 "없음"을 캐시해 뒀으면, 바로 배포한 새 워커는 시드로
   떨어져 다른 정답을 낸다
3. 배포
4. `POST /api/giveup`으로 정답이 그대로인지 확인

```bash
# 고정
node workers/api/node_modules/wrangler/bin/wrangler.js kv key put \
  "answer:2026-08-14" 507 --namespace-id 2a3cd2b09d28426294afd33c6b2d8ebb --remote
# 확인
node workers/api/node_modules/wrangler/bin/wrangler.js kv key get \
  "answer:2026-08-14" --namespace-id 2a3cd2b09d28426294afd33c6b2d8ebb --remote
```

2026-08-14 배포 때 실제로 이걸 놓칠 뻔했다 — 예약 트리거가 09:10이었는데 퍼즐 리셋도
09:00이라, 고정 없이 나갔으면 09:00~09:10에 시작한 사람들의 정답이 도블에서 판타지
왕국으로 바뀌었을 것이다.

### 예약 배포 작업 (`bomantle-deploy`)

트리거를 제거해 뒀다(자동 실행 없음). 작업 정의는 남아 있으므로 수동 실행:

```powershell
Start-ScheduledTask -TaskName 'bomantle-deploy'
```

⚠️ 다시 예약을 걸 때는 **트리거 날짜를 미래로 바꾼 뒤** 켤 것. `StartWhenAvailable=True`라
지난 트리거로 Enable하면 "놓친 일정"으로 판단해 즉시 실행된다.

⚠️ 배포는 **작업 트리**에서 나간다(커밋 여부와 무관). 예약 실행 전에 트리 상태를 확인할 것.
